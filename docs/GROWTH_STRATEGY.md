# Organic Growth Strategy

## The 100,000-star ambition

100,000 GitHub stars is an ambitious distribution outcome, not an engineering acceptance criterion and not something that can be guaranteed. The project earns stars only if developers can understand it quickly, run it reliably, trust its legal model, and show it to others.

## A product hook people can explain

**"A universal watchlist that tells you where a title is legally free to watch — and proves why the source is allowed."**

That message is more distinct than "another free streaming app." The proof-of-rights model, regional availability, source health, and open adapter contract should be visible in the product and repository.

## What must exist before a major launch

1. A working live demo and Android installable build.
2. A 60–90 second screen-recorded walkthrough using real, authorized content.
3. README screenshots, architecture diagram, security model, and a three-minute quick start.
4. A public roadmap, issue templates, Discussions, contribution guide, and response expectations.
5. At least one complete end-to-end use case, tested on a low-end Android device and a mobile browser.
6. Transparent licence boundaries: MIT covers code, not film, artwork, metadata, or provider assets.

## Distribution loop

- Developers: publish technical decisions, API docs, adapter SDK examples, and reproducible local setup.
- Users: short demos showing search → rights proof → official playback → synced list.
- Maintainers: label small good-first issues, review contributions consistently, and publish changelogs.
- Communities: launch only after a usable demo; tailor a real walkthrough to self-hosting, Android, open-source, media accessibility, and privacy communities.
- Reach: use release notes, project blog posts, conference demos, and honest comparison pages.

## 90-day execution framework

### Days 1–30: credibility
Make web and Android builds reproducible, land the catalogue contract, finish CI, publish architecture/security docs, and ship the first testable demo. Recruit a small group of technical reviewers.

### Days 31–60: usefulness
Deliver search, title pages, a verified sample catalogue, watchlists, localization, and one permitted playback integration. Publish a real performance and rights audit.

### Days 61–90: distribution
Ship a public beta, release installable builds, publish a walkthrough, run focused community launches, and improve onboarding from actual user feedback.

## Metrics that matter

Track weekly active users, successful first-run completion, search-to-title conversion, authorized playback success, crash-free sessions, contributor retention, PR review time, docs completion, and release adoption. Stars are a lagging signal; never optimize for them at the expense of users or legal compliance.

## Never do this

No bought or botted stars, fake contributors, mass unsolicited spam, misleading feature claims, fake demo content, fabricated download numbers, or unauthorized media to create a viral impression.
